# Authenticated paper-trading API

This branch adds a Vercel Node.js Function at `/api/paper-trades` and a database RPC migration.

## What it does

- Requires a Supabase access token on every request and verifies it with Supabase Auth.
- Uses `SUPABASE_SERVICE_ROLE_KEY` only inside the server function; it must never use a `VITE_` prefix or be committed.
- GET returns up to 100 paper trades belonging only to the authenticated user.
- POST validates the basic shape of a paper trade and calls a transactionally idempotent database function.
- The database function inserts the trade and its first audit event in one transaction.
- A database trigger rejects updates/deletes to paper-trade event history.
- No wallet, signing, swap, or live-order functionality is included.

## Required Vercel environment variables

Set these in the Vercel project that builds the app, for Preview and Production only when appropriate:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`

The service-role key is a secret. Never place it in frontend environment variables, source code, GitHub Actions logs, browser storage, or client-side bundles. Configure it only in Vercel's server-side environment settings.

## Required database step

Apply migrations in order to the intended Supabase project:

1. `supabase/migrations/202610300001_paper_trading.sql`
2. `supabase/migrations/202610300002_paper_trading_api.sql`

Do not apply these to an unrelated Supabase project. The migration has not been run by this repository change.

## Important trust boundary

The API authenticates the user and validates persistence input. It does **not** independently verify the submitted scanner/security evidence, fetch a fresh market quote, or prove an executable fill. A browser-submitted simulation is still user-submitted data. Until server-side market-data acquisition and scanner evaluation are implemented, records must be treated as unverified paper simulations—not validated signals, performance evidence, or profitability claims.

## Request shape

`POST /api/paper-trades` with `Authorization: Bearer <Supabase access token>` and JSON body:

```json
{ "trade": { "idempotencyKey": "...", "chain": "solana", "status": "OPEN", "strategy": "solana-paper-v1" } }
```

The example is abbreviated; the endpoint requires all fields generated by `paperExecutor`.

`GET /api/paper-trades` uses the same authorization header.
